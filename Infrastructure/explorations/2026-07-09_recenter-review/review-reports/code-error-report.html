CE-001
Hard-coded sibling-repo path in the raw-ORG directory fallback
code/01_data_preparation/01h_nonemployed_pool.py · Line 162–170 · Python
LOW
Problematic Code
code/01_data_preparation/01h_nonemployed_pool.py:162
def _find_raw_org_dir() -> Path | None:
    env = os.environ.get("EIG_ORG_RAW_DIR", "")
    cands = ([Path(env)] if env else []) + [
        PATH_PROJECT / "data" / "raw" / "cps_org",
        PATH_PROJECT.parent / "EIG-Wage-Figure-Explain-Everything" / "data" / "raw" / "cps_org"]
    for c in cands:
        if c.is_dir() and list(c.glob("year=*/part-0.parquet")):
            return c
    return None
Why This Is Wrong
The second fallback candidate hard-codes a specific sibling-repository directory name (EIG-Wage-Figure-Explain-Everything) relative to the project parent. On any checkout where that sibling repo is absent or named differently, and where EIG_ORG_RAW_DIR is not set, the function silently returns None and the pipeline falls back to a synthetic pool — producing different results with only a printed warning, not an error. This is the classic "works on the author's machine" portability pattern. The identical _find_raw_org_dir() is duplicated in code/01_data_preparation/01i_household_links.py (line 55–64), so both stages share the fragility.
Recommended Fix
# Prefer an explicit, documented config/env contract and fail loudly when the
# real data is expected but missing, rather than silently degrading to synthetic:
cands = ([Path(env)] if env else []) + [PATH_PROJECT / "data" / "raw" / "cps_org"]
# Optionally read additional search roots from cfg (e.g. cfg["org_raw_search_dirs"])
# so the sibling-repo location is configuration, not a literal in two files.
Move the sibling-repo location into configuration (or require EIG_ORG_RAW_DIR) and factor the shared helper into one module so 01h and 01i cannot drift. Severity is LOW because the current behavior degrades gracefully with a warning rather than corrupting output.

Semicolon-packed weighted-quantile one-liners hinder readability

def wmed(v, w):
    v = np.asarray(v, float); w = np.asarray(w, float); ok = ~np.isnan(v) & (w > 0)
    if ok.sum() == 0: return np.nan
    v, w = v[ok], w[ok]; i = np.argsort(v); cw = np.cumsum(w[i]); return float(v[i][np.searchsorted(cw, cw[-1]*0.5)])

# and, at line 704:
def wq(x, qq):
    i = np.argsort(x); cw = np.cumsum(wt[i]); return float(np.asarray(x)[i][np.searchsorted(cw, cw[-1]*qq)])
Why This Is Wrong
These weighted-quantile helpers pack four to six statements onto single lines with semicolons, and the same sorted-cumulative-weight logic is re-implemented in at least three places (here, in 02f line 106–107, and in the R wmed of 05c/05d). The logic is correct, but the density makes it hard to audit — this is the exact "opaque one-liner replaceable with named steps" case in the readability checklist.
Recommended Fix
def weighted_quantile(x, w, q):
    x = np.asarray(x, float); w = np.asarray(w, float)
    ok = ~np.isnan(x) & (w > 0)
    if not ok.any():
        return np.nan
    x, w = x[ok], w[ok]
    order = np.argsort(x)
    cw = np.cumsum(w[order])
    return float(x[order][np.searchsorted(cw, cw[-1] * q)])
Expanding to one statement per line and centralizing a single weighted_quantile helper (imported by 01h/02f) removes the duplication and makes the aggregation step reviewable.
