Appendix L81, L83 give the absolutes: "recalibrating on the employment-stock base moves total entry from 0.83 to 0.71 million ... single-mother entry from 0.13 to 0.19 million"; spouse-zeroing "moves the central estimate from 0.83 to 0.69 million; assuming 80 percent take-up scales it to 0.66 million."
What the Code Does

# are all computed on the FLOOR path (penalty 0, 0.83M base):
#   spouse-zeroed:        0.83 -> 0.69   (~ -16.9% ~ "a sixth")
#   80% take-up:          0.83 -> 0.66   (~ -20%   ~ "a fifth")
#   employment-stock base: 0.83 -> 0.71 ; single mothers 0.13 -> 0.19
# No equivalent rows are regenerated on the 1.25M evidence-central pool.
Why This Is Inconsistent
The main draft frames all three sensitivities as excursions from the 1.25M evidence-central (expressed as ratios — "a sixth," "a fifth"), but the underlying code and the appendix compute them on the 0.83M floor pool and report floor absolutes (0.69M, 0.66M, 0.71M). Applying the floor ratios to the evidence-central is a defensible approximation, but it is not what the code actually ran, and the appendix simultaneously calls 0.83M "the central estimate" (see CC-001). The result is that the two drafts disagree on what base these sensitivities modify. Because sensitivities are exactly where a skeptical reader looks, the base should be stated unambiguously.
What to Check
  • Either regenerate the spouse-zero / take-up / employment-stock rows on the evidence-central pool, or state explicitly that the reported ratios are measured on the floor and applied proportionally to 1.25M.
  • Reconcile the appendix absolutes (0.69 / 0.66 / 0.71M) with the main draft's "evidence-central" framing so both drafts name the same base.
  • Confirm the employment-stock single-mother figures (0.13 → 0.19M) are the intended floor-path values, not evidence-central.
