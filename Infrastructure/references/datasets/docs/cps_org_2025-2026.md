# CPS Outgoing Rotation Group (IPUMS-CPS basic monthly) — variable documentation

- **Dataset:** Current Population Survey, Outgoing Rotation Group / Earner Study (IPUMS-CPS basic monthly microdata).
- **Registry id:** `cps` (variables appended to the curated `template` entry at `verification: parsed`).
- **Vintage documented:** IPUMS-CPS basic monthly ORG, post-2023m3 `*2` era, most-recent-12-months pool (2025–2026). **The ORG extract has not been submitted yet**; exact samples resolve at extract time (approximately `cps2025_06` … `cps2026_05`).
- **Consumers:** `code/01_data_preparation/01a_data_ingest.py` (eligible-worker build), `code/01_data_preparation/01h_nonemployed_pool.py` (non-employed matching pool), `code/01_data_preparation/00_export_org_data.py` (column export from the sibling `real-wages-generations-ipums` ORG panel).

## Sources and authority tiers

This is a **planning-stage** documentation pass done headless (no external fetch). Facts are drawn from three in-repo tiers, and every field that cannot be confirmed from in-repo material is marked `[unverified: ...]`:

1. **Tier 1 — Authoritative in-repo IPUMS DDI.** `data/external/asec_2025_raw/cps_00305.xml`, an IPUMS-CPS DDI 2.5 codebook (IPUMS CPS **Version 13.0**, DOI 10.18128/D030.V13.0, produced 2026-03-09) for the project's ASEC 2025 extract (March 2025 sample; March Basic + ASEC). A copy is cataloged at `Infrastructure/references/literature/data_dictionaries/2025_cps-asec_dictionary.xml`. IPUMS variables are *integrated* (harmonized) across CPS samples, so the value labels and general definitions this DDI states for shared variables carry over to the basic-monthly ORG extract. **Caveat (DD-2):** the DDI's per-variable **universe** statements describe the ASEC 2025 sample; the basic-monthly ORG universe should be reconfirmed against the ORG extract's own DDI, except where the IPUMS universe text explicitly generalizes to basic monthly (noted per variable, e.g. EARNWT).
2. **Tier 2 — In-repo pipeline documentation.** `docs/org_integration_methodology.md` and the Python consumers. These transcribe some codebook facts (notably WKSTAT labels from "IPUMS DDI codebook for extract #304") and define the wage/hours variables operationally. They are **not** the authoritative ORG DDI; definition/universe fields not confirmable from the codebook are flagged.
3. **Tier 3 — Requested but undocumented in-repo.** Variables on the task list that are neither in the vendored R extract's variable list (`docs/org_integration_methodology.md` §13) nor referenced by the examined consumers. All substantive fields are `[unverified: ...]` and require a human-approved authoritative IPUMS ORG DDI fetch.

> Observed facts (from the DDI/docs) are stated plainly; anything the source does not state is marked `[unverified: ...]`. No universe, definition, question wording, or code was inferred from a variable name.

## Tier 1 — variables confirmed against the in-repo IPUMS DDI (cps_00305.xml, IPUMS CPS v13.0)

### YEAR — Survey year
- **Definition (DDI):** "YEAR reports the year in which the survey was conducted."
- **Coding:** 4-digit numeric.
- **Universe:** All records. (Technical variable.)

### MONTH — Month of interview
- **Definition (DDI):** "MONTH indicates the calendar month of the CPS interview."
- **Coding:** `01` January … `12` December.
- **Consumer use:** `(year, month)` groups count the pooled months; the ORG weight is divided by the number of unique year-month cells (`01a`, `01h`).

### CPSIDP — Longitudinal person identifier
- **Definition (DDI):** IPUMS-CPS-defined identifier that uniquely identifies individuals across CPS samples via the 4-8-4 rotation pattern (max 8 appearances, indexed by MISH). DDI advises verifying links with AGE, SEX, RACE.
- **Coding:** 14-digit numeric.
- **Comparability:** DDI notes erroneous links can occur from source-data errors; CPSIDV is a demographically validated alternative.

### EARNWT — Earnings (Outgoing Rotation / Earner Study) weight
- **Definition (DDI):** Person-level weight to be used in any analysis including EARNWEEK, HOURWAGE, PAIDHOUR, UNION, UHRSWORKORG, WKSWORKORG, ELIGORG, OTPAY.
- **Universe (DDI, generalizes to basic monthly):** From 1998 onward, individuals age 16+ in rotation groups (MISH) 4 or 8 who are **not self-employed**. The DDI states explicitly: "This universe also applies to basic monthly samples after 2010." Persons in the 6 non-earner-study rotation groups have EARNWT = 0; armed forces have EARNWT = 0 even in rotations 4/8.
- **Coding:** 8-digit with 4 implied decimals; IPUMS command files divide by 10,000.
- **Why it matters:** EARNWT is the correct weight for the employed-earner wage statistics in `01a` (dynamic weighted-median wage, eligible-worker counts). It is ~0 for non-earners, which is why the non-employed pool in `01h` must use WTFINL instead. The pipeline converts monthly ORG weights to an annual-average population weight via `earnwt / n_months`.

### AGE — Age
- **Definition (DDI):** "Age gives each person's age at last birthday."
- **Coding:** integer years; `00` = under 1 year; `90` (90+, 1988–2002); top codes `99` = 99+.
- **Consumer use:** eligibility restricted to ages 16–64 (`01a`, `01h`); 65+ excluded as a Social-Security-recipient proxy.

### SEX — Sex
- **Definition (DDI):** "SEX gives each person's sex."
- **Coding:** `1` Male, `2` Female, `9` NIU.
- **Consumer use:** `01h` sets `sex_label = Male` iff `SEX == 1`, else `Female`; drives the matching cell (men vs. women).

### RACE — Race
- **Definition (DDI):** CPS race categories; multiple-race reporting since 2003 (up to 26 codes since 2013).
- **Coding (selected):** `100` White, `200` Black, `300` American Indian/Aleut/Eskimo, `650/651/652` Asian or Pacific Islander, `700` Other single race, `801`+ multiple-race combinations, `999` Blank.
- **Consumer use:** `01h` design matrix uses `RACE == 200` (Black) and `RACE not in {100,200}` (other race) dummies.

### HISPAN — Hispanic origin
- **Definition (DDI):** Identifies and classifies persons of Hispanic/Spanish/Latino origin (question wording changed in 2003 to "Are you Spanish, Hispanic, or Latino?").
- **Coding (selected):** `000` Not Hispanic, `100`–`612` specific Hispanic origins, `901` Do not know, `902` N/A.
- **Consumer use:** `01h` treats `HISPAN > 0` as Hispanic.

### MARST — Marital status
- **Definition (DDI):** Current marital status, including whether the spouse lives in the same household.
- **Coding:** `1` Married, spouse present; `2` Married, spouse absent; `3` Separated; `4` Divorced; `5` Widowed; `6` Never married/single; `7` Widowed or Divorced; `9` NIU.
- **Consumer use:** `_family_key` treats MARST ∈ {1,2} as "married", else "single".

### NCHILD — Number of own children in household
- **Definition (DDI):** Counts own children of any age/marital status residing with each individual, including step- and adopted children; 0 if none. IPUMS-derived from IPUMS family interrelationships.
- **Coding:** `0`–`9` (`9` = 9+).
- **Why it matters:** with MARST, NCHILD drives `family_type_key` (`single_0c | single_2c | married_0c | married_2c`) and the single-mother matching cell (`single_2c`). Per methodology doc §15.3, NCHILD is confirmed populated in basic monthly (28% of the 2025 ORG panel report ≥1 child).
- **Comparability note:** DDI label says "own children of any age"; the export-doc comment (§5) describes NCHILD as children **under 18**. Recorded here as stated; the "under 18" restriction is `[unverified: not in the DDI text, which says any age]`.

### RELATE — Relationship to household head
- **Definition (DDI):** Relationship to the head of household/householder; 4-digit codes consistent with IPUMS-USA.
- **Coding (selected, DDI 4-digit):** `0101` Head/householder; `0201` Spouse; `0202` Opposite sex spouse; `0203` Same sex spouse; `0301` Child; `0303` Stepchild; `0501` Parent; `9999` NIU.
- **Why it matters:** the tax-dependent exclusion in `01a` drops `relate == 301` (child of household head) with `age < 19`. Note the consumers read the parquet integer form (leading zero dropped), so DDI `0301` → integer `301`, `0201` → `201`, `0202` → `202`, `0101` → `101`. PROJECT.md's "spouse is 202, children are 301" corresponds to DDI `0202` (opposite-sex spouse) and `0301` (child). The methodology doc §15.3 confirms `101` (reference person) as the dominant 2025 code.
- **Comparability note:** DDI codes are from the ASEC 2025 sample; the ORG extract should carry the same IPUMS-integrated 4-digit scheme, but the exact set of populated codes for basic monthly 2025–2026 is `[unverified: pending ORG DDI]`.

### EDUC — Educational attainment recode
- **Definition (DDI):** Highest year of school or degree completed; combination of HIGRADE and EDUC99. The general version is the first two columns.
- **Coding (selected):** `000/001/002` NIU/none/preschool; `010`–`070` grades 1–12; `071` 12th grade no diploma; `073` HS diploma or equivalent; `080/081` some college; `091/092` Associate's; `111` Bachelor's; `123` Master's; `124` Professional; `125` Doctorate; `999` Missing.
- **Consumer use:** `_EDUC_MAP` groups codes into Less-than-HS / HS-GED / Some-college-Associate's / Bachelor's / Graduate. (Note: the consumer map uses `71/73`, `81/91/92`, `111`, `123/124/125` — consistent with the DDI codes above.)

### EMPSTAT — Employment status
- **Definition (DDI):** Labor-force status (working, seeking work, unemployed, or NILF activity). Armed forces coded NIU in the source employment-status variable.
- **Coding:** `00` NIU; `01` Armed Forces; `10` At work; `12` Has job, not at work last week; `20/21/22` Unemployed (general/experienced/new); `30`–`36` Not in labor force (housework, unable, school, other, unpaid <15h, retired).
- **Why it matters:** `01h` defines "employed" as EMPSTAT ∈ {10, 12}; the complement (working-age, valid WTFINL) is the non-employed pool.

### CLASSWKR — Class of worker
- **Definition (DDI):** Whether self-employed, private/public employee, armed forces, or unpaid family worker; classified by the job with the most hours.
- **Coding:** `00` NIU; `10` Self-employed; `13` Self-employed not incorporated; `14` Self-employed incorporated; `20`–`28` wage/salary (private/government detail); `29` Unpaid family worker; `99` Missing.
- **Consumer use:** EPI sample eligibility excludes self-employed. Methodology doc §4.5/§15.1 treats CLASSWKR `10`–`14` as self-employed (excluded).

### PAIDHOUR — Paid by the hour
- **Definition (DDI):** Dichotomous indicator of whether the respondent is paid by the hour for the current job. One of the Outgoing Rotation/Earner Study questions; DDI advises using EARNWT.
- **Coding:** `0` NIU; `1` No; `2` Yes; `6` Refused; `7` Don't Know.
- **Consumer use:** `PAIDHOUR == 2` routes to directly reported hourly wage (HOURWAGE2/HOURWAGE); otherwise wage = weekly earnings / usual hours (`01h`, methodology §4.4).

### STATEFIP — State (FIPS code)
- **Definition (DDI):** Household state of residence in FIPS coding (alphabetical).
- **Coding:** standard 2-digit FIPS `01`–`56` plus historical combined-state codes (`61`–`90`) and `99` (state not identified).
- **Consumer use:** mapped to two-letter abbreviation via a 51-entry FIPS table (50 states + DC) in `01a`/`01h`; rows with unmapped FIPS are dropped (`01a`) or defaulted to `TX` (`01h`).

## Tier 2 — variables from in-repo pipeline docs/code (NOT the authoritative ORG DDI)

### MISH — Month in sample (rotation)
- **Definition (in-repo doc):** CPS rotation index. The Earner Study / ORG questions are asked only in rotation months **4 and 8** (`MISH %in% c(4,8)`), roughly 1/4 of basic-monthly respondents each month (methodology §3, §4.1).
- **Consumer use:** `01h` restricts the Heckman estimation sample to `MISH ∈ {4,8}` (where wages are observed).
- **Coding / universe:** `[unverified: full 1–8 rotation coding and DDI universe not in an in-repo codebook; needs ORG DDI]`.

### WTFINL — Final basic-monthly person weight
- **Definition (in-repo doc/code):** Basic-monthly final person weight covering the civilian non-institutional population, including the unemployed and NILF (export-doc comment; `01h`). Unlike EARNWT (≈0 for non-earners), WTFINL is populated for the non-employed.
- **Why it matters:** WTFINL is the correct population weight for the non-employed matching pool in `01h` (`weight = WTFINL / n_months`). Also present in the curated `cps` template `weights` (basic monthly person; census `PWSSWGT`).
- **Coding / universe:** `[unverified: implied-decimal scaling and exact DDI universe not confirmed in-repo; needs ORG DDI]`.

### HOURWAGE2 — Hourly wage rate (`*2` successor, paid-hourly workers)
- **Definition (in-repo doc):** Harmonized/rounded hourly wage rate for paid-hourly workers; the preferred `*2`-era successor to legacy HOURWAGE, used after the 2023m3 redesign (methodology §4, §4.4; preference "HOURWAGE2 preferred, HOURWAGE fallback").
- **Universe:** paid-hourly ORG earners (PAIDHOUR == 2); `[unverified: exact DDI universe pending ORG DDI]`.
- **Coding / sentinel:** `[unverified: exact HOURWAGE2 sentinel not stated in-repo]`. The pipeline strips the legacy HOURWAGE at `≥ 999.99` (`01h` line 106); the corresponding HOURWAGE2 magic value is not documented in-repo.
- **Comparability:** legacy HOURWAGE vs. HOURWAGE2 differ across the 2023m3 break; the pipeline prefers HOURWAGE2 and falls back to HOURWAGE.

### EARNWEEK2 — Usual weekly earnings (`*2` successor)
- **Definition (in-repo doc):** Rounded/harmonized usual weekly earnings before taxes and deductions from the **primary job** (base pay plus usual tips/commissions/overtime; excludes bonuses, irregular payments, and secondary-job earnings). Preferred `*2`-era successor to legacy EARNWEEK (methodology §4.2).
- **Coding / sentinel:** values `≥ 999,999.99` treated as missing (methodology §4.2 table); legacy EARNWEEK sentinel is `≥ 9,999.99`. `01h` applies era-specific sentinels (`*2` era ≥ 999999.99 after 2023m3; legacy ≥ 9999.99 before).
- **Topcoding:** pre-April-2023 EARNWEEK was topcoded at a sex-varying fixed threshold (~$2,884.61/week for men); the pipeline applies a Pareto imputation above the threshold and a MISH-8 phase-in harmonization for April 2023–March 2024 (methodology §4.5 E4/E5). Post-April-2023 uses a BLS dynamic cap.
- **Universe:** `[unverified: exact DDI universe pending ORG DDI]`.

### UHRSWORK1 — Usual hours per week at main job (basic monthly)
- **Definition (in-repo doc):** Usual weekly hours at the main job, basic-monthly version (methodology §4.3).
- **Coding:** values `≥ 997` treated as invalid/missing; hours > 99 treated as outliers and set missing.
- **Consumer use:** preferred hours source over UHRSWORKORG in the wage denominator.
- **Universe:** `[unverified: exact DDI universe pending ORG DDI]`.

### UHRSWORKORG — Usual weekly hours (ORG/Earner Study version)
- **Definition (in-repo doc):** Usual weekly hours, Outgoing Rotation supplement version (methodology §4.3).
- **Coding:** `997` = hours vary week to week (triggers hours-vary imputation); `998/999` = invalid/NIU (`≥ 997 → NA`).
- **Universe:** ORG earners; `[unverified: exact DDI universe pending ORG DDI]`.

### WKSTAT — Full/part-time work status
- **Definition (in-repo doc, DDI-transcribed):** BLS full/part-time work-status recode. Codes and labels transcribed in methodology §15.3 from "the online IPUMS DDI codebook for extract #304 (CPS Basic Monthly, WKSTAT variable, start position 145, width 2)" and confirmed against `wkstat.value_counts()` on `org_panel_2025.parquet` (n=296,369).
- **Coding (methodology §15.3):** `11` FT hours (35+), usually FT; `12` PT non-economic, usually FT; `13` Not at work, usually FT; `14` FT hours, usually PT economic; `15` FT hours, usually PT non-economic; `21` PT economic, usually FT; `22` PT hours, usually PT economic; `41` PT hours, usually PT non-economic; `42` Not at work, usually PT; `50` Unemployed seeking FT; `60` Unemployed seeking PT; `99` NIU/blank/NILF. Aggregate codes `10/20/40` do not appear in post-2000 data.
- **Why it matters:** WKSTAT drives the annual-hours weeks multiplier in `01a` (`annual_hours = hours_epi × weeks_multiplier(WKSTAT)`): 11→52, 12→48, 13→52, 14→40, 15→48, 21→40, 22→40, 41→48, 42→48; `50/60/99` filtered (no valid wage); default 52 for unclassified.
- **Universe:** `[unverified: exact DDI universe pending ORG DDI]`. Labels are DDI-sourced but transcribed via the methodology doc, not a vendored ORG DDI.
