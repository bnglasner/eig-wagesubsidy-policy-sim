# Requirements Specification: Internalize the CPS ORG wage build (EIG-Wage-Figure → wage-subsidy-sim)

**Date:** 2026-07-07
**Status:** DRAFT (awaiting approval)
**Save Location:** `Infrastructure/specs/2026-07-07_org-wage-internalization.md`

## Objective

Stand up the CPS ORG wage-construction pipeline **inside** this repo — by vendoring the canonical EIG-Wage-Figure R stages (config + annotated inert-guards only), scoped to the most recent 12 complete monthly CPS samples — and **adapt this repo's Python stages to consume the EIG-Wage-Figure repo's native wage elements** (values and process), so the 80-80 subsidy simulation no longer depends on the sibling repo at run time.

## Direction decided with the user (2026-07-07)

The original brief assumed the vendored R would reproduce the defunct `real-wages-generations-ipums` EPI-named schema (`hourly_wage_epi`, `hours_epi`, `epi_sample_eligible`, `paid_hourly`, `weekly_earn_epi`). It cannot: the canonical repo (`EIG-Wage-Figure-Explain-Everything`) does not emit those columns. The user chose the better long-term fix:

> "We should be replacing the EPI elements with the elements generated by the EIG repo … Use only the EIG wage figure repo process and values and incorporate them into this repo's code … adapt the wage sim repo to use the elements created in the EIG-wage-figure repo."

Therefore the **adapter is Python-side**: the wage-subsidy Python stages are rewired to read EIG-native columns and reproduce the EIG hourly-wage value by the EIG formula. The vendored R stays as faithful as possible (config + inert-guards). Bit-exact byte-parity is relaxed to **faithful method replication** on the new window ("get as close as possible").

## Source of truth

- Canonical repo: `EIG-Wage-Figure-Explain-Everything` at commit **`33bbcb7`** (recorded for drift control).
- Canonical stages: `code/00a_download-ipums-cps.R`, `code/01a_load-ipums-cps.R`, `code/01b_build-org-panel.R`, plus the **nominal** hourly-wage routing at the top of `code/02a_build_real_wages.R` (deflation excluded).

## R → Python handoff contract

**Raw partitions** `data/raw/cps_org/year=YYYY/part-0.parquet` (consumed by `01h`): UPPERCASE IPUMS names, `haven` labels zapped to plain numeric/integer; includes `YEAR, MONTH, MISH, CPSIDP, EARNWT, WTFINL, AGE, SEX, RACE, HISPAN, MARST, NCHILD, RELATE, EDUC, EMPSTAT, CLASSWKR, PAIDHOUR, HOURWAGE2, EARNWEEK2, HOURWAGE_CANON_NUM, EARNWEEK_CANON_NUM, UHRSWORK1, UHRSWORKORG, WKSTAT, STATEFIP, OCC2010, CITIZEN, IND1990, UNION`, Q-flags. All rotations (non-employed retained).

**Gated panel** `data/intermediate/cps_org_panel/year=YYYY/part-0.parquet` (consumed by rewired `01a`): the raw columns for gate-passing rows plus `uhrsworkorg_used_num`, `nominal_weekly_wage_num`, `hours_imputed_flag`, `pareto_topcode_imputed_flag`.

**Python-derived (in 01a), feeding unchanged `hourly_workers.parquet`:** `employer_wage = max(nominal_hourly_wage, 7.25)`, `hours_epi = uhrsworkorg_used_num`, `annual_hours = hours_epi × weeks_multiplier(WKSTAT)`, family/state/demographic fields, subsidy fields. Dtypes: float64 wages/hours/weights, string state/family/demographic keys.

## Extract definition (for the M13 human-gate)

- Collection: `cps` (IPUMS-CPS), `data_format="fixed_width"`, `data_structure="rectangular"`.
- Samples: the most recent **12** complete monthly `cpsYYYY_MM` samples at run time (≈ `cps2025_06` … `cps2026_05`, subject to IPUMS release lag).
- Variables: per M4 (with `data_quality_flags=TRUE` on `HOURWAGE2`,`EARNWEEK2`).
- Expected size: ~12 monthly basic files (~150k persons each) → order 1.8M person-rows; on-disk raw `.dat.gz` well under 1 GB (Tier 2). Confirm exact samples + variable list before submit.
