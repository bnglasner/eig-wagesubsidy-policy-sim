CE-001
Demographic aggregation indexes a positionally-filtered array with original DataFrame labels
code/02_descriptive_analysis/02a_descriptive_stats.py · Lines 214–222 (function _agg_by_group) · Python
HIGH
Problematic Code
code/02_descriptive_analysis/02a_descriptive_stats.py:214
workers = workers[valid_mask]
net_income_delta = net_income_delta[valid_mask.values]   # positional filter -> length m
rows = []
groups = workers.groupby(col, observed=True)
for label, grp in groups:
    w  = grp["weight"].values
    gs = grp["subsidy_annual"].values
    nd = net_income_delta[grp.index]     # grp.index = ORIGINAL row labels, NOT 0..m-1
Why This Is Wrong
net_income_delta is a NumPy array. The line net_income_delta = net_income_delta[valid_mask.values] filters it positionally, producing a length-m array indexed 0..m−1. However, workers = workers[valid_mask] keeps the original index labels (with gaps), so inside the group loop grp.index contains original labels that can range up to N−1 (the pre-filter row count). net_income_delta[grp.index] then performs NumPy fancy indexing that treats those labels as positions into the length-m array. Whenever valid_mask drops at least one row (m < N): if any surviving label is ≥ m it raises IndexError and halts the stage; if by chance all surviving labels are < m it silently returns the wrong worker's net-income delta, corrupting avg_net_income_gain. It is currently masked only because, in the present data, all four demographic filters (by_sex, by_race_ethnicity, by_education, by_age_bin) happen to drop zero rows — but _educ_group() can emit "Unknown" and sex_label/race_ethnicity can be missing, either of which triggers the bug. The sibling stages 02b (_scenario_costs) and 02d (_ni_cost, _entrant_fiscal, _NetIncome) all use the correct b.index.get_indexer(idx) pattern, confirming this line is the anomaly.
Recommended Fix
workers = workers[valid_mask].reset_index(drop=True)
net_income_delta = net_income_delta[valid_mask.values]
rows = []
groups = workers.groupby(col, observed=True)
for label, grp in groups:
    w  = grp["weight"].values
    gs = grp["subsidy_annual"].values
    nd = net_income_delta[grp.index]     # now grp.index is 0..m-1, aligned with the array
Adding .reset_index(drop=True) re-bases the DataFrame index to 0..m−1 so it aligns positionally with the filtered array (matching the intent). Equivalently, replace the indexing line with nd = net_income_delta[workers.index.get_indexer(grp.index)] to adopt the same positional-lookup idiom the 02b/02d siblings use.

Why This Is Wrong
Not a correctness bug. _entrant_hours_by_mode reads hourly_workers.parquet and recomputes the incumbent cell assignment on every call, and entrant_hours_sensitivity calls it once per mode (three times). Because entrant_hours_sensitivity is itself invoked from both 02d and again from 02g on the evidence-central pool, the same file is read several extra times per pipeline run.
Recommended Fix
def entrant_hours_sensitivity(pool, beta, target):
    inc = pd.read_parquet(PATH_DATA_PROCESSED / "hourly_workers.parquet")
    inc_cells = _b.assign_cell(inc)
    for mode in cfg[...]["entry_hours_modes"]:
        h = _entrant_hours_by_mode(pool, mode, inc=inc, inc_cells=inc_cells)
Read the incumbent file once and pass it (with its precomputed cells) into the per-mode helper. Cheap change; removes redundant disk I/O and duplicated assign_cell work.

Why This Is Wrong
Not a correctness bug. These per-row Python comprehensions / .apply() calls run once per record over the full pooled CPS ORG panel (many hundreds of thousands of rows). Each is a pure categorical recode expressible as a vectorized np.select / Series.map on integer bins, which is substantially faster and avoids per-element Python-object overhead.
Recommended Fix
# age_bin via vectorized cut:
out["age_bin"] = pd.cut(out["age"], [-1, 24, 34, 44, 54, 64, 200],
                        labels=["16-24","25-34","35-44","45-54","55-64","65+"])
# race_ethnicity via np.select on the race/hisp arrays;
# family_type_key via boolean masks on marst / nchild.
Replace the element-wise loops with vectorized pandas/NumPy operations. Behavior is unchanged; only speed improves. Low priority given a single build per run.

Why This Is Wrong
Not a correctness bug. The state-level and demographic-level pct_in_group denominators each glob and read the same org_workers_*.parquet file and re-apply the same base-mask filter. When the external file is present this doubles the disk read and the filtering work. (In the current checkout the file is absent, so both blocks fall through the empty-glob branch; the concern is latent.)
Recommended Fix
Load the ORG file and compute the filtered org_base once near the top of main(), then derive both the state totals and the demographic-group totals from that single in-memory frame. Removes the duplicated read and keeps the two denominators guaranteed consistent.
